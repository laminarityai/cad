# Research

ADR-0009 and its amendment: a material value the table lacks is researched, not left unknown. When a check reads a material field the table marks `unknown`, the result's `reads` has a `missing` entry and the scorecard's `research` holds a request: brief id, key, field, unit and the accepted range. The agent reads the value from a page and calls `submit_research(brief_id, key, field, value, unit, url, quote)`. The server trusts the agent's unit and converts it by the exact table in `cad.research.fields`. A spelling that differs from a key only in case, such as "Mpa", names that key. It makes two checks (`cad.research.quote`), and neither reads a unit, a label or prose. First, `value` must be written in the quote as one number: "1.24" and "1,24" write 1.24, "1.24e3" writes 1240, and "124", "1.245", "D638" and "cm3" do not write 1.24, 638 or 3. Second, the server fetches the page (https on port 443 only, public addresses only, checked again after every redirect, a 4 MiB cap, one 15 s deadline over the whole fetch, no credentials) and checks that the quote is on it. That comparison uses only letters and numbers, case folded, so whitespace, punctuation, markup and table pipes may differ. A quote may not start or end inside a number. An accepted value is a signed record in `$CAD_HOME/.cad/projects/<project_id>/research/<n>.signed`, in the field's canonical unit, with the url, title, quote, fetch date and page hash. It fills the field for that project only and never replaces a known value. A key with no git row, such as `acme-pla`, fills the project's own row `project-acme-pla`. A result that reads it has a `researched` read with the url, quote and page hash, and a requirement it decides has `basis` `researched`.

## Sub-features

- `research-request` makes `score_variant` with a brief return a `research` request for each missing material value a check read. Missing geometry never asks.
- `research-accept` stores the agent's value from a quote on a fetched page, converted by the unit table, and the next `score_variant` reads it, with table version `<git>+<project_id>@r<n>`.
- `research-refuse` refuses, each with a reason and a new request: a unit the table has no key for (the reason lists the spellings), a value the quote does not write as one number, a value outside the request's range (these three before any fetch), a failed or guarded fetch, a quote not on the page (the reason quotes the page's text around the value, when the page writes it), and a value that breaks the table's rules. A field that is already known, cited or researched, is refused with no request.
- `research-current` keeps a card current when a later record fills a value the card never read. `evals/briefs/trace_store.py --root <home>/.cad/variants --briefs-root <home>/.cad/briefs --projects-root <home>/.cad/projects` rebuilds each card's table from the first `n` records its version names, and reports `stale: 0`.
- `research-unreadable` covers a project ledger the store cannot read. `submit_research` refuses before the fetch with no new request, and `score_variant` puts the problem in `research_problem` and asks for no research.

## Driving it with cad-call

Run every call with `HOME="$CAD_HOME"`, a fresh directory, so nothing writes to the operator's `~/.cad` (issue #81). Create a brief for a PETG cantilever (100 x 20 x 10 mm box, `flat_end` support, 10 N `far_end` load across the long axis) with a `max_deflection` 2 mm requirement, and confirm it with no model: `create_brief` and `propose_requirements` through `cad-call`, then `ask_to_confirm` with `PATH="$CAD_BROWSER/bin:$PATH"`, as [Briefs](./briefs.md) says. Build the box with the `brief_id`, then score it with `material_key` `prusament-petg` until nothing is pending (`prusament-pla` has a cited `poisson_ratio`, so it asks for no research):

- `fea` is `unknown`, its `reads` lists `poisson_ratio` as `missing`, and `research` has one request for `poisson_ratio` with `low` 0, `high` 0.5 and `exclusive` true.
- `HOME="$CAD_HOME" uv run cad-call submit_research '{"brief_id": "<brief_id>", "key": "prusament-petg", "field": "poisson_ratio", "value": 0.35, "unit": "", "url": "https://pmc.ncbi.nlm.nih.gov/articles/PMC8123144/", "quote": "the Poisson ratio = 0.36, was used"}'` returns `refused` with "the value 0.35 is not written in the quote as one number", before any fetch.
- The same call with `"value": 0.36` and `"quote": "The Poisson Ratio = 0.36 was used"` (case and a comma differ from the page) returns `accepted` with `value` 0.36, `unit` `dimensionless` and `record` 1.
- Score again: `fea` decides, its `reads` has `researched` for `poisson_ratio` with the url and quote, the requirement has `basis` `researched`, and `research` is gone.
- The same call with `"value": 0.4` returns `refused` with "already has a researched poisson_ratio" and no request.
- A table row, a page of another shape: `polymaker-polymax-pc` has `poisson_ratio` unknown. `{"key": "polymaker-polymax-pc", "field": "poisson_ratio", "value": 0.37, "unit": "", "url": "https://www.azom.com/article.aspx?ArticleID=1934", "quote": "The Poisson ratio of polycarbonate is 0.37"}` returns `refused` with "does not appear on" and "the page writes 0.37 here", quoting the table's text. The same call with `"quote": "Poisson's ratio | 0.37"` returns `accepted` with `record` 2.
- A project row and a unit: `{"key": "acme-pla", "field": "density", "value": 1.25, "unit": "g/cm3", "url": "https://wiki.polymaker.com/polymaker-products/more-about-our-products/documents/technical-data-sheets/petg-pet/polylite-tm-petg", "quote": "Density | ISO1183, GB/T1033 | 1.25 g/cm3 at 23°C"}` returns `accepted` with `key` `project-acme-pla` and `value` 1250 in `kg/m^3`.
- `trace_store.py` (see `research-current`) reports `numbers resolved: 30, stale: 0`.

## Gotchas

- Quote the words and number in the page's order. Markdown pipes, spacing and `<sup>` splits do not matter, but a symbol the page has between the label and the number, such as "ν" in "Poisson's ratio ν 0.38", does: leave it in or start the quote after it.
- Pass the number as the quote writes it, and the unit the page gives it. A value the agent converted, such as 1240 kg/m^3 from "1.24 g/cm3", is refused as not written in the quote.
- The server does not check the unit. 75 ksi from "Tensile Strength (MPa) 55-75" is accepted as 517 MPa, and the labelled, cited verdict is what shows the mistake.
- Many sites answer the server's fetch with HTTP 403, and PDFs are refused. The request then asks for another page. On 2026-11-08, 11 of 40 likely research sites answered 403 (matweb, makeitfrom, specialchem, mdpi, sciencedirect, researchgate, wiley, acs, tandfonline, curbell, ulprospector). PMC, Wikipedia, engineeringtoolbox, azom, simplify3d and the Prusa and Bambu wikis answer 200.
