# Research

ADR-0009 and its 2026-11-08 amendment: a material value the table lacks is researched, not left unknown. When a check reads a material field the table marks `unknown`, the result's `reads` has a `missing` entry and the scorecard's `research` holds a request: brief id, key, field, unit and the accepted range. The agent reads the value from a page and calls `submit_research(brief_id, key, field, value, unit, url, quote)` with the value and unit as the page writes them and the quote it read them from. The server checks that `unit` is a spelling in the field's exact table (`cad.research.fields`) and that `value` is written in the quote, in any of the page's formats ("1.24", "1,24", "1.24e3", "8 960"), then fetches the page (https on port 443 only, public addresses only, checked again after every redirect, a 4 MiB cap, one 15 s deadline over the whole fetch, no credentials) and checks that the quote is on it (`cad.research.quote`). That comparison folds case and Unicode forms and uses only letters, digits and decimal marks, so spacing, markup and table pipes do not matter, and a quote never starts or ends inside a number. It reads no labels, units or prose. An accepted value is a signed record in `~/.cad/projects/<project_id>/research/<n>.signed`, in the field's canonical unit, with the url, title, quote, fetch date and page hash. It fills the field for that project only and never replaces a known value. A result that reads it has a `researched` read with the url, quote and page hash, and a requirement it decides has `basis` `researched`.

## Sub-features

- `research-request` makes `score_variant` with a brief return a `research` request for each missing material value a check read. Missing geometry never asks.
- `research-accept` stores the agent's value from a quote on a fetched page, converted by the unit table, and the next `score_variant` reads it, with table version `<git>+<project_id>@r<n>`.
- `research-refuse` refuses, each with a reason and a new request: a unit the table has no key for (the reason lists the spellings), a value the quote does not write, a value outside the request's range (these three before any fetch), a failed or guarded fetch, a quote not on the page (the reason quotes the page's text around the value, when the page writes it), and a value that breaks the table's rules. A field that is already known, cited or researched, is refused with no request.
- `research-current` keeps a card current when a later record fills a value the card never read. `evals/briefs/trace_store.py --root <home>/.cad/variants --briefs-root <home>/.cad/briefs --projects-root <home>/.cad/projects` rebuilds each card's table from the first `n` records its version names, and reports `stale: 0`.
- `research-unreadable` covers a project ledger the store cannot read. `submit_research` refuses before the fetch with no new request, and `score_variant` puts the problem in `research_problem` and asks for no research.

## Driving it with cad-call

Run every call with `HOME` set to a fresh directory, so nothing writes to the operator's `~/.cad` (issue #81). Create a brief for a PLA cantilever (100 x 20 x 10 mm box, `flat_end` support, 10 N `far_end` load across the long axis) with a `max_deflection` 2 mm requirement, and confirm it with the scripted person as [Briefs](./briefs.md) says, through a server started with `--opener .claude/skills/verify/scripts/human.py`. Build the box with the `brief_id`, then score it with `material_key` `prusament-pla` until nothing is pending:

- `fea` is `unknown`, its `reads` lists `poisson_ratio` as `missing`, and `research` has one request for `poisson_ratio` with `low` 0, `high` 0.5 and `exclusive` true.
- `uv run cad-call submit_research '{"brief_id": "<brief_id>", "key": "prusament-pla", "field": "poisson_ratio", "value": 0.35, "unit": "", "url": "https://pmc.ncbi.nlm.nih.gov/articles/PMC8123144/", "quote": "the Poisson ratio = 0.36, was used"}'` returns `refused` with "the value 0.35 is not written in the quote", before any fetch.
- The same call with `"value": 0.36` and `"quote": "the Poisson ratio = 0.30, was used"` returns `refused` with "does not appear on" and the page's text around 0.36.
- The same call with `"value": 0.36` and `"quote": "the Poisson ratio = 0.36, was used"` (a sentence; the old quote reader refused it) returns `accepted` with `value` 0.36, `unit` `dimensionless` and `record` 1.
- Score again: `fea` decides, its `reads` has `researched` for `poisson_ratio` with the url and quote, the requirement has `basis` `researched`, and `research` is gone.
- A table row of another shape: `bambu-pla-basic` has `yield_strength` unknown. `{"key": "bambu-pla-basic", "field": "yield_strength", "value": 43, "unit": "MPa", "url": "https://fiberlogy.com/en/filaments/asa-en/asa-asa-en/", "quote": "Tensile strength at yield: 43 MPa (ISO 527)"}` returns `accepted`, or `refused` with "breaks the table's rules" when 43 MPa is not below the cited tensile strength.

## Gotchas

- Quote the words and number in the page's order. Markdown pipes, spacing and `<sup>` splits do not matter, but a symbol the page has between the label and the number, such as "ν" in "Poisson's ratio ν 0.38", does: leave it in or start the quote after it.
- Pass the number as the quote writes it and the unit the quote gives. A value converted by the agent, such as 1240 kg/m^3 from "1.24 g/cm3", is refused as not written in the quote.
- Many sites answer the server's fetch with HTTP 403, and PDFs are refused. The request then asks for another page. On 2026-11-08, 11 of 40 likely research sites answered 403 (matweb, makeitfrom, specialchem, mdpi, sciencedirect, researchgate, wiley, acs, tandfonline, curbell, ulprospector). PMC, Wikipedia, engineeringtoolbox, azom, simplify3d and the Prusa and Bambu wikis answer 200.
