# Auto mode

The server holds an Auto run. The agent calls `auto_start`, then `auto_revise` with each new revision of the code, until the server returns `Stopped`. A run stops when every checked requirement passes, when a call proposes requirements or a row waits on a confirmation, when the agent calls `auto_ask`, when the account's usage cap refuses a build (`AccountLimit`), or when the person presses Stop. `bounds_conflicts` stops a run before any build, and the confirmation page warns of the same conflict before the person confirms.

Design: `docs/design/phase-4.md` §1b, §2.5 (ADR-0010) and §2.7 (`AccountMeter`). Units 7 and 9 of §4.

## The chat's part

The chat agent runs the loop ([Chat](chat.md)). The server holds the rule, and the chat holds none:

- After every tool call it reads the run's signed log. When the run has stopped, whoever stopped it, it posts a `stop_report` event, with the server's reason and report, and ends the turn. The person's Stop while a turn runs is reported the same way, and the agent's next call is refused by the server.
- When the agent ends a message with the run still running, it posts a `driver` reminder to call `auto_revise` or `auto_ask`, at most three times in a turn. Then the turn ends and the run stays Running.
- A message that continues a run is watched too. A run that stopped before the message was reported by the turn that stopped it.

## The checks §4 gives units 7 and 9

- Unit 7, Auto core: table tests for all pass, pending not counting toward all pass, proposing requirements stopping the run, `auto_ask` stopping it with the agent's note, and a cap refusal stopping it with `AccountLimit`. A scripted driver that keeps calling after `Stopped` is refused with no container started. An agent measurement cannot change `step`.
- Unit 9, conflict exit eval: on "fits in a 20 mm cube, PLA, at least 50 g" the confirmation page warns of the conflict, and the run stops with `NeedsPerson(conflict)` and its `Bounds` before any build. On a stiffness-versus-mass brief the agent stops and reports within 6 revisions, with a note that names both requirements.

## How to get to it

- **Through the chat, scripted.** Start `cad-http` as in [Chat](chat.md), put the conversation in Auto with `curl -X PUT localhost:8765/v1/conversations/$CID/mode -H "cookie: __session=$PERSON_A" -H "content-type: application/json" -d '{"mode": "auto"}'`, and post one message to a script that calls `create_brief`, `propose_requirements`, `ask_to_confirm`, `auto_start`, then `auto_revise` with the plate code. The stream ends with `stop_report` (reason `all_pass`) then `turn_ended`. The run log under `<account base>/projects/` shows `auto_start`, at least one `auto_revise` and `Stopped`.
- **The person's Stop.** While the script's turn runs, `PUT` the mode to `design`. The stream shows the next call refused and a `stop_report` with reason `stopped_by_person`.
- **With a headless client.** confirm a brief (browser as the person), `auto_start`, `auto_revise` with the plate code, then call `auto_revise` again after `Stopped` and show the refusal with no new container (`docker ps -a --filter label=cad.sandbox` before and after). Cost: docker + browser.
- **The conflict exit, in process.** `uv run python evals/briefs/run.py --driver inprocess --briefs ~/cad-evals/briefs --out <dir> --only conflict-cube` builds the hosted app in the process, puts a conversation in Auto, posts the brief through the chat routes and lets the scripted person confirm the page. The default model is `scripted`, a script built from the brief's grader. The line it prints is `conflict-cube: pass, conflict, 0 revisions, 0 variants`. `<dir>/conflict-cube/auto.json` holds the `Bounds`, the conversation's mode (`design`), `variants` 0 and `containers` 0 (the account's meter holds no `reserve` line), and `events.json` the stream. Run it with `--opener "$CAD_BROWSER/bin/open"` to watch the confirmation page in the browser, where B's warning shows the same pair. Cost: no model, no Docker, about 2 s.
- **The same, on a live model.** Add `--model claude-haiku-4-5-20251001`. The driver reads the key from `~/.config/cad/anthropic.env` when `ANTHROPIC_API_KEY` is not set, as `cad-http` does. With no key in either place the driver exits 1 and names `ANTHROPIC_API_KEY` before it builds anything. The live agent sees only the brief text. It stops with `conflict` only when it names a material the table holds (`made_of` with a `list_materials` key) because the server reads the density by exact key (ADR-0009); a generic key such as `pla` has no density, so the run starts and the agent must find the conflict itself. `propose_requirements` tells the agent to call `list_materials` first; four of four runs before that sentence missed the conflict. Cost: live, under a minute.
- **The stiffness-versus-mass brief** is `conflict-stiffness-mass` in the same set. The scripted run stops with `agent_asked` and no build. On a live model the run must stop with `agent_asked` within 6 revisions and a note that names both requirements and says they conflict, which `autoresult.judge` checks by keyword from the `expect` block in the brief's grader. Read the note too: an agent that stops because a material value is missing has not found the conflict. `prusament-pla` now cites a Poisson's ratio of 0.34 (Song et al. 2017, Table 6), measured on printed unidirectional PLA specimens, so `fea` decides on it. On Haiku, three of three runs still failed: one picked `bambu-pla-basic`, which has no Poisson's ratio, and stopped for it after 8 revisions; one stopped after 6 revisions to ask about build failures; one used `prusament-pla`, `fea` decided, and the note named both requirements and the conflict, but after 9 revisions, more than 6.
- The conflict warning is built and has its recipe in [Briefs](../briefs.md) (Conflict warning).

`uv run pytest tests/evals/test_inprocess_driver.py -q` runs the in-process driver on a cube brief in the test's own words (a stop with `Bounds`, the conversation in Design, no variant, no container), a brief that agrees, a failed expectation, and a live model with no key. `uv run pytest tests/chat/test_auto_driver.py -q` runs a run to all pass, a run stopped by `auto_ask`, a call refused after `Stopped`, the person's Stop in a turn, and the reminders.
